## ACP/MCP 间歇性失败 — 不是协议缺陷

**根因**：健康门是 **5 分钟缓存**；拉不起来的 MCP server 在**启动时即被判 down 并从注入中排除** ⇒ **持续坏掉的 server 永远不会让会话失败**。那句不透明错误只出现在「**上次体检 ok、之后 ≤5 分钟内坏掉**」的窗口里 —— 这就是「间歇」。

**三个假设的裁决**：H3（名字 `mcp` 对不上）**推翻**（`mcp-client(mcp)` 是 harness 自己的子系统名）· H2（MCP server 回连 daemon）**推翻**（`serve_stdio` 是纯 stdio→HTTP 桥，启动阶段不联系 daemon）· H1 **一半成立一半证伪**（注入目标确实是 `CARGO_TARGET_DIR` 那个 exe，但 daemon 在跑时文件被锁、链接器换不掉 ⇒ 不会产生半截 exe）。

**修复**：错误现在带**服务器名 + 命令 + 原始错误**；harness 之前预检；失败后并发补做真握手。16 条回归测试（核心断言：错误里必须出现服务器名与命令）。
