## 2 逐条守卫形状（输入 · 判据 · 成本 · 假阳性风险 · 不机械化的后果）

### G-21（第 21 条）把已有的 `check-workflow-refs.sh` 接进 CI —— **建议先做**
* **形状（接线，零新代码）**：在 `ci.yml` 的一个 job 里加一步：
  * 输入 = `.github/workflows/*.yml`（脚本默认全扫）；
  * 判据 = 脚本自身：workflow 在 `jobs:` 内**未加引号**引用的 `*.sh|*.mjs|*.js|*.ts|*.ym*l|*.json|*.toml|*.sql|*.ps1` 路径，必须在 **同一个提交**里被 `git ls-files` 跟踪；`working-directory:` 必须存在且含至少一个被跟踪文件；相对路径按**该 step 自己的工作目录**解析。
  * 额外对照（我建议同批加进同一脚本或另一步）：**报告类文档不得用 `git diff` 给未跟踪文件背书**——这条**不要**做成"扫 docs 找 git diff"（见下 FP），而是做成 **G-21b 证据工具**（报告期用）。
* **成本**：实现 **≈0**（脚本已在仓库、8.4 KB、注释里写明判据与豁免）；CI **<1s**；维护面 **极低**（只在 workflow 新增引用时要管）。
* **假阳性风险：极低**。理由：该脚本的头部注释就是一份「如何不误报」的设计说明 —— 它自己是**欠近似**的（只扫 `jobs:`、剥注释、`echo/printf` 不算引用、只算**未加引号**的 token、含 `$`/`*`/`{}` 的当运行期值、`working-directory` 在每个 `- name:`/`- uses:` 边界重置）。它还**记录了两个真实误报类**（天真版本）：① `scripts/build-panel.mjs`、`tools/design-audit.mjs` 其实是 `panel/scripts/…`/`panel/tools/…`（**相对路径按 step 的工作目录解析**才修掉）；② 文档头部注释里的路径是**散文**（剥注释才修掉）。⇒ 我的建议**不重写它**，只接线；若要改动，必须保留这两条豁免并加负控。
* **不机械化的后果**：任何人（含我）都可能把新的 workflow 引用到一个未提交的脚本上 ⇒ **push 后 main 直接红**，且 `test-evidence.sh` 的 5 处调用同时失效。今天**没有任何东西**在拦它 —— 脚本躺着不跑，等于没有。
* **可证伪验收**：在 CI 日志里看到该步名字与 0 退出；**负控** = 故意引用一个未跟踪的脚本 ⇒ 该步 `::error::` 且 job 红。

### G-15②（第 15 条第二条）夹具自清断言 —— **建议先做**
* **形状（测试内断言，按 crate 分摊）**：每个会**写输入**的 fixture 在拆除后断言：
  * 输入 = 它自己创建的临时 root / 表行 / 端口；
  * 判据 = 「**我建的**已删且可再次创建」：① 目录不存在（或目录内 0 文件）；② 用同一个 pid/seq 再建一次**不冲突**（这条正是 t42 的病：pid 回收后撞 `UNIQUE(entities.id)`）；③ 断言必须**在连接关闭之后**执行（`Drop` 在连接仍开时失败是 t42 的原始成因）。
  * 形状参考：`crates/graph/tests/fixture.rs` 的 `Drop`（`crates/graph/tests/live-after.rs` 已有 `#[ignore]` 的活库副本仪器，但**共用一个副本文件**⇒ 一次跑全部必崩，t42 第 1 条）。
* **成本**：每个 fixture **≈10 行**；CI 增量 ≈0（跑在既有测试里）；维护面低。
* **假阳性风险：低**——它只判**自己建的**输入（自归因），不判共享 `%TEMP%` 的状态 ⇒ 不会重演「把队友的目录算我头上」。
* **不机械化的后果**：**偶发红**（单跑不复现）会被当成被测代码的 bug；本代已发生一次整套门禁 `3 passed; 2 failed`，并留下 **725 个**泄漏目录。
* **可证伪验收**：禁用清理（故意不删）⇒ 断言红；恢复 ⇒ 绿（**坏侧好侧都测到**，即 §6.0 第 15 条第②点的要求）。

### G-12（第 12 条）公开面快照 + 增量打印
* **形状（新脚本 + baseline）**：
  * 输入 = 指定 crate 的 `src/**/*.rs`；
  * 生成 = 逐行归一后排序的清单：`pub fn/struct/enum/trait/const/static/type` 的**名字+签名骨架**（类型名与参数类型，剥掉泛型参数名与文档注释/行号）+ `pub use` 的**re-export 名单** + 标了 `#[derive(…Serialize/Deserialize…)]` 的类型的**字段名与类型**；
  * 判据 = 与 `docs/design/reviews/.api-baseline/<crate>.txt` **逐行 diff**；有 delta ⇒ **不直接红**，而是**打印 delta 并要求同一提交内更新 baseline**（更新动作就是「我承认改了形状」），未更新才红。
* **成本**：实现 **中**（≈40 行脚本 + 一次生成 baseline；不需要 nightly/`cargo public-api`）；CI **~1s**；维护面 **中**（每次故意改 API 都要更新 baseline —— 这是**有意的**摩擦，正是第 12 条要的）。
* **假阳性风险：中**，可压到低：必须归一（排序、剥注释、剥行号、泛型参数名归一、`where` 子句归一）；**否则行重排/格式化会 churn**。**已知的坑**（本代教训）：`ScoreKind` 的 `serde` 形状与 `as_str()` 的冻结字面量不一致（契约 F-5）⇒ **快照必须同时记 `#[derive]` 与手写 `as_str()` 两处**，否则「serde 漂移」这一最贵的类还是漏。
* **不机械化的后果**：跨 crate 形状变更只能靠「同伴从一次红里猜」（契约第 12 条自己记了两个实例）；破坏面包括 `RetrievalHit` 加字段会让 `chat.rs`/`runs.rs` 编不过。
* **可证伪验收**：给一个 crate 加一个 `pub fn` ⇒ 该步打印出这一行 delta 且不更新 baseline 时红；更新 baseline ⇒ 绿；**负控** = 只改文档注释 ⇒ **不**产生 delta（证明归一化有效）。

### G-20（第 20 条）把解析出的命令行打进 CI 并与判据对账
* **形状**：CI 里加一步：`scripts/cargo-team.ps1 test --workspace -DryRun`（**已有开关**，见脚本 `:36/:424`）⇒ 打印解析出的**真实命令行**（`cargo test --workspace …` + target/jobs/cpus/priority）；判据 = 打印行与门禁声明里写的那条**逐字一致**（面板侧同理：`panel/scripts/build-panel.mjs` 已被 `ci.yml:338` 的 "Typecheck + build" 覆盖，可在同一步 echo 它跑的四步）。
* **成本**：实现 **极低**（只加 echo 步骤）；CI ≈0；维护面极低。
* **假阳性风险：低**（纯回显 + 字符串比对；`-DryRun` 的解析被 `-DryRun` 自测过）。
* **不机械化的后果**：本代已两次因「只读入口名字」写出错前提（`panel` 的 `build` 到底含不含 `tsc`），其中一次**被写进 `AGENTS.md` 传播了两次**。
* **可证伪验收**：改一次包装脚本的默认参数 ⇒ 该步打印的行变化（证明它真在回显**解析结果**而不是常量）。

### G-15③（第 15 条第三条）临时 root 泄漏增量
* **形状**：跑测试前后各数一次 `%TEMP%\ruagent-*`，增量 >0 时**打印**（`--warn`，**不 fail**）。**可归因的加强版**：只有「本进程 pid + 本 crate 名 + 本轮时间窗」的目录才算我的 —— 这仍然会在共享 `%TEMP%` 里撞上队友（**与 F5 纪律直接冲突**）。
* **成本**：低（≈20 行）；CI ≈0；维护面低。
* **假阳性风险：中～高**（共享 `%TEMP%` 的增量不可归因）。
* **判定**：**只报不判**（warn-only），真正该做的替代是 **G-15②**（自归因）。**不建议**把它做成 fail 的门禁。

### G-21b（第 21 条的“证据面”）证据工具（不是门禁）
* **形状**：`scripts/evidence.ps1 <path…>` 对每个路径打印一行：`tracked|untracked`（`git ls-files --error-unmatch`）+ `sha256` + 行数 + mtime。
* **用例**：任何报告要声称「这个文件没被改 / 改了 N 行」时，**先跑它**；`untracked` ⇒ 明确写「`git diff` 对本文件不是证据，改用内容级读数（哈希/行数/数字序列）」（契约第 21 条 + t80 §修订 R-2 的同一教训）。
* **成本**：低（≈30 行）；CI 0（报告期工具）；维护面极低。
* **假阳性风险：极低**（只报事实，不做判断）。

## 3 明确**不建议机械化**的三条（给抽检触发条件）

| 条 | 为什么不建议 | 抽检的**触发条件** | 抽检要看的**读数** |
| --- | --- | --- | --- |
| **13** 同形多处替换必须一次改完 | 门禁分不清「队友正在改」与「我读错了」；`git status` 在共享树里不是证据（本代已误归因过一次） | 门禁日志里出现 **`error[E0xxx]` 指向「不存在的函数/类型」** 且被报者**不是**该文件在途改动的属主 | 报错文件 + 行号 + 报者的 `git status` 时间点；**只报坐标、不代改**（F5） |
| **14** 根因必须受控反做 | 判据是**行为归因**（采样面/聚合口径/缓存/并发/tie），而「根因」二字在纯机械因果里也合法出现 ⇒ 机械扫描必然误报 | 报告里出现**推断性**归因（含「采样面 / 聚合口径 / 缓存 / 并发 / 排序 tie / 偶发」等词）且该归因**支撑一条判据或结论** | 「把 X 改回去，症状是否仍在」的**两次读数**（反做后症状仍在 ⇒ X 不是根因）；RV-C r3 的示范形状 |
| **18** 异步面必须先轮询终态 | 静态无法判定「读得够不够晚」；`sleep` 也不等于正确（t48 是「读得够晚」的运气） | 任何对**异步面**（wiki build / run / distill / 索引）的读数 | 探针里**等到什么状态**（`done`/`failed`）、**等了几轮**；断言里出现终态字段 |

* **替代品（建议做，成本低）**：把「等到终态」的 helper 放进共享测试工具（例如 `wait_for_status(url,直到 done|failed, 轮数上限)`），让**默认写法就是对的**；helper 由 G-15② 的自清断言顺带受益。
