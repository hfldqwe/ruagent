## 1 职责与首要任务

**职责**：**权限收件箱**——智能体要做规则未覆盖的操作时停在这里等人裁决（允许 / 拒绝 / 取消，或选一个具体 option）。
**首要任务**：**安全而快速地裁决**。"快速"是因为正在跑的运行被阻塞在这上面；"安全"是因为这是一页**有后果**的页面。

据此决定：
- 卡片**左侧 3px 琥珀脊线**（`.inbox-card` 的 `box-shadow: inset 3px 0 0 var(--signal), var(--panel-shadow)`）——这是 MASTER §3.2 白名单 **W3「等你处理」**，本页是该语义最纯粹的使用场景，必须保持。
- 每张卡**默认展开可读的裁决信息**：工具名 + `title` + 来源运行号 + 选项按钮；`raw_input` 放浮层（可能很大），但入口必须显眼。
- 裁决按钮**按 `choices[].kind` 排序与配色**（allow 类在前、reject 类次之、cancel 最后），不按后端返回顺序——顺序错了会点错。
- **2s 轮询**（本页与 App 外壳各有一个 `permissions` 轮询，实测 11.5s 内 12 次请求 = 两个轮询器叠加）：规格要求**合并为一个**（行 28；这也是全站唯一有硬证据的超额轮询）。
- 空态是**常态**（大多数时间没有待裁决项）：空态文案必须解释"什么时候会出现在这里"，现状已做到，保留。

## 3 层级

**本页最大元素 = `.view-bar h2`（title 20/26 w600）**，实测 `maxFs = 20`、**≥18px 节点 1 个（空态）/ 1+N（有 N 条待裁决）**。

为什么本页**不应该**有仪表盘：待裁决项的数量已经出现在**两个更近的地方**——侧栏导航项上的 `.nav-badge`（`App.tsx` 的 `inboxCount`）和 `.view-bar` 副题。再加一条顶部读数会把"当前需要我做什么"的注意力从卡片上移走。
**行 6 的处理**（与 chat / settings 同一类问题）：本页的"大元素"是**卡片本身**（`.inbox-card` 有 3px 琥珀脊 + 材质），不是文字。规格给出可机器判定的口径，并在 §8 I2 登记为需要 MASTER 裁决的例外——**2026-09-21 已落槌：MASTER §12.1 把它列入豁免清单**（门槛 ≥1 + 必须有 20px 层级中心）：

> 有 N≥1 条待裁决时：≥18px 节点 = `h2`(20) + 每条卡片的 `title`(20/26，工具名是**唯一必须看清的字段**，值得 title 档) → **1 + N**，N≥2 即满足行 6。
> 空态（N=0）：只有 `h2`，**登记为行 6 的第二个例外**（与 chat 空态、settings 同类）。

次级：`.ev-icon`（13px 图标）；按钮文字 13/18；`.muted.mono` 运行号 11/15。

**禁止**：给整张卡染琥珀底（只有 3px 脊线是信号，卡片仍是 panel 材质）；给"允许"按钮用绿色（`allow` 是**主操作**，用 `primary`（琥珀）——这是 W4，与本页的 W3 同一颜色、同一含义"现在需要你"，两者共现是自洽的）。

## 4 内容模型

| 调用 | 返回类型（`api.ts`） | 用到字段 | 展示位 |
|---|---|---|---|
| `api.pendingPermissions()`（**2s 轮询** —— **t50 后由应用外壳持有该轮询器**，仅在 `#inbox` 让渡给本页；本页只消费，不再自开轮询器） | `{ pending: PendingPermission[] }` | `run_id, tool_call_id, title, raw_input, choices: { option_id, name, kind }[]` | 卡片列表与浮层 |
| `api.resolvePermission(runId, toolCallId, answer)` | — | `answer: { action: "allow" \| "reject" \| "cancel" } \| { option_id: string }` | 裁决按钮；成功后该卡从列表移除（等下一次轮询即可，**不做乐观更新**） |

**字段 → 展示位**

| 展示位 | 字段 | 规则 |
|---|---|---|
| 卡片主标题 | `title` | **必须 title 20/26**（见 §3） |
| 副标记 | `run_id.slice(0,8)` | `.muted.mono`；**不得做成链接**（`run_id` 不是 `task_id`，无法直接跳转——规格明确禁止） |
| 按钮组 | `choices[]` | `option_id` → `resolvePermission(..., { option_id })`；`kind` 决定顺序与样式 |
| 兜底按钮 | — | `choices` 为空时显示 `allow`/`reject`/`cancel` 三个固定动作 |
| 浮层 | `raw_input` | `JSON.stringify(..., null, 2)` 放进 `<pre class="raw">`；`raw_input` 类型是 `unknown`，**必须容错**（字符串/数组/null 都要能渲染） |
| 徽标 | `pending.length` | 侧栏 `.nav-badge`（W3）与折叠态 `Badge` |

**分组**：无分组（一维队列）。**排序**：按 `run_id` → `tool_call_id` 升序（现状顺序随 API；2s 轮询时卡片可能重排 —— 在一页有后果的页面里，按钮位置跳一下就可能点错）。
**密度上限**：

| 项 | 实测 | 上限 | 手段 |
|---|---|---|---|
| 待裁决卡 | 0 | **≤30** | 超出「还有 N 条，请先处理上面的」；**不得分页**（阻塞队列分页会把阻塞藏起来） |
| `choices` 数 | 0 | ≤6（超出折叠进「更多选项」） | — |
| `raw_input` 大小 | — | ≤64KB 直接渲染；超出显示「输入过大（N KB）」 | 防一次超大 JSON 卡死页面 |
| `title` 长度 | — | 单行省略 + `title` 全量 | — |
| 页高 | 844px（空） | ≤6000px | — |
| 节点数 | 126 | ≤1500 | — |

## 5 四种状态

| 态 | 契约 | 现状 |
|---|---|---|
| **loading** | `pending === null` → 需补 `Spinner`（**现状直接渲染空态**）→ 规格要求：首次加载显示 `Spinner`，**轮询刷新不改变已有内容**（不闪） | **违反（轻微）** |
| **empty** | `pending.length === 0` → `Empty icon="inbox"` + 「收件箱是空的」+ hint「当智能体要做规则未覆盖的操作时会出现在这里。配置审批智能体可实现无人值守。」（**全站写得最好的一处空态**，一字不改保留） | ✅ |
| **error** | ①`api.pendingPermissions()` 的 `catch` 现状**把失败当成"没有待裁决项"** → 渲染空态「收件箱是空的」。**这是全站最危险的错误态**：运行正被阻塞，而页面说"没事"。规格要求：`role=alert`「无法读取权限队列 · 重试」+ **保留上一次列表** + 侧栏徽标显示「—」而不是 0 ②`resolvePermission` 失败：按钮旁 `role=alert` + 该卡保持可见（**禁止乐观移除**，否则一次失败会让人以为已裁决） | **严重违反（行 20）** |
| **密集** | 见 §4 上限。额外：①2s 轮询**必须与 App 外壳的轮询合并**（现状两个轮询器 → 实测 11.5s 内 12 次 `/permissions`）②`document.hidden` 时暂停 ③轮询期间已渲染卡片的按钮不得重建（`key` 用 `run_id:tool_call_id`，现状 ✔） | ①**违反** ②待实现 |
